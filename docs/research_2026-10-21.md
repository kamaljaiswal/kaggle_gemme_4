# Research: how to improve the agent (21 Oct 2026)

## 1. Where the competition stands

- Public leaderboard (CLIST snapshot, 21 Oct): 0.24 for the top 2 teams, **0.22 for 32 teams**, 0.20 for the next 16.
  The board scores 58 tasks, so 0.22 is 13 tasks and 0.24 is 14.
- The 0.22 agent family is public, and identical files score 0.13-0.22 across reruns (see `submissions/LOG.md`).
  The top of the public board is mostly the same agent with luck. The final private board uses other tasks.
- Hidden tasks come from **private repositories**. Tricks that only help FastAPI or Rich (for example `docs_src/`
  examples) may not transfer; generic behaviour fixes matter more.

## 3. What our own data says

- Failures on our 12 tasks: wrong edit in the right file (3-5), budget (2-5), never edited (2, both FastAPI docs tasks).
- Malformed `edit_file` calls are common: 21 failed calls in one task; one task needed 67 LLM turns for 26 calls in
  v3 and 29 in v4 after a "switch to a Python script after one failure" rule.
- Untracked files are graded; `submit_patch`/`get_status` report patch_size 0 for them; a timed-out command returns
  no output (timeout probe).
- Thinking is 59-86% of output time on 4xL4.

## 5. Realistic target

The same-family agent averages about 0.15 per run. A real gain is solving a few more tasks every run (+3 to +5 of 120),
which only paired local runs on many valid tasks can show before the final selection.
